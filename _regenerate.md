# Regenerating this dictionary

The column/row-count tables in `01_*.md` through `06_*.md` were generated by introspecting the live database, not hand-typed. Re-run these against `tower_mobility_db1` to refresh them (row counts and any newly-added columns will drift over time; table groupings and narrative sections are hand-written and should be reviewed/edited directly).

## Column metadata for `std` + `ref` schemas

```sql
SELECT
    s.name AS schema_name,
    t.name AS table_name,
    c.column_id,
    c.name AS column_name,
    ty.name AS data_type,
    c.max_length,
    c.is_nullable
FROM sys.tables t
JOIN sys.schemas s ON s.schema_id = t.schema_id
JOIN sys.columns c ON c.object_id = t.object_id
JOIN sys.types ty ON ty.user_type_id = c.user_type_id
WHERE s.name IN ('std','ref')
ORDER BY s.name, t.name, c.column_id
```

## Row counts

```sql
SELECT s.name AS schema_name, t.name AS table_name, SUM(p.rows) AS row_count
FROM sys.tables t
JOIN sys.schemas s ON s.schema_id = t.schema_id
JOIN sys.partitions p ON p.object_id = t.object_id AND p.index_id IN (0,1)
WHERE s.name IN ('std','ref')
GROUP BY s.name, t.name
```

## Primary keys

```sql
SELECT s.name AS schema_name, t.name AS table_name, c.name AS column_name
FROM sys.key_constraints kc
JOIN sys.tables t ON t.object_id = kc.parent_object_id
JOIN sys.schemas s ON s.schema_id = t.schema_id
JOIN sys.index_columns ic ON ic.object_id = kc.parent_object_id AND ic.index_id = kc.unique_index_id
JOIN sys.columns c ON c.object_id = ic.object_id AND c.column_id = ic.column_id
WHERE kc.type = 'PK' AND s.name IN ('std','ref')
```

## Checking whether a `dbo` shadow table is stale (the pattern from `00_START_HERE.md`)

For any table that exists in both `dbo` and `std`/`ref`, compare freshness before trusting either:

```sql
SELECT COUNT(*), MAX(<a date/time column>) FROM dbo.<table_name>;
SELECT COUNT(*), MAX(<a date/time column>) FROM std.<table_name>;  -- or ref.
```

If `dbo`'s max date lags noticeably behind `std`/`ref`'s, it's a dead shadow copy — don't query it, and check whether any production script still references it unqualified (`grep -rn "FROM table_name\b" --include=*.py` without a schema prefix in front).

No `MS_Description` extended properties were found on any `std`/`ref` table or column as of 2026-08-25 — this document is currently the only source of business-context documentation for this database. If descriptions get added directly in SQL Server later (`sp_addextendedproperty`), the column-metadata query above can be extended to pull `sys.extended_properties` and merge them in.
